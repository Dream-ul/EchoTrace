# 整理调查来源

为当前节点研究准备原始来源。来源整理是 Researcher 的工作步骤，不是单独 Agent 或独立交付物；最终仍须提交符合节点合同的 `NodeDraft`。

## 规则

1. 围绕 NodeSpec 的研究问题和首选来源类型搜索；优先获取官方原文、直接相关材料及独立来源。
2. 搜索结果标题、摘要和 URL 只是线索；用当前任务可用的 `fetch_public_page`、`ingest_public_feed` 等工具获取正文。网页抓取结果由应用归一化并存入当前调查，不能声称执行过未调用的工具。
3. 依据规范 URL、内容哈希和来源身份识别重复或转载材料。转载可用于研究传播路径，但不能当作独立印证。
4. 对每条证据保留精确原文片段和定位信息；只有搜索摘要、正文不可访问或定位不稳定的材料，不能支撑事实性主张。
5. 来源缺失、访问失败或身份不明时，在 NodeDraft 的结论中准确说明其对本节点的限制，不补造正文、时间、哈希或发布者信息。
6. 使用一条或多条原始来源自行归纳主张，并把证据片段绑定到主张。最终交付 `NodeDraft`，不输出独立来源清单。

## 交付边界

搜索、网页抓取、RSS 读取、规范化和持久化由已加载的业务工具执行。工具返回的来源对象可供节点研究使用；不要把工具结果改包装成未接入主链的 `collection_scope`、`captures` 或 `normalized_records` 清单。来源记录和原始正文留在来源存储中，NodeDraft 只保留需要的 `document_id`、证据片段和定位。
